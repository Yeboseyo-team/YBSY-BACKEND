## 1. 문서 개요

이 문서는 「학기예보」 v1.0을 2026년 10월 20일까지 개발·배포하기 위해 팀이 합의할 요구사항을 정의합니다. 근거는 2026년 10월 13일 제출한 서비스 제안서이며, 제안서에 없던 구현 결정(예: 시험 주차 컬럼, 온보딩)은 "보완"으로 표시했습니다.

### 1.1 범위

- 포함: 회원 인증, 학기 계획 등록, 자격증 일정 반영, 주차별 부담 예보, 등록 전 사전 검토 (필수 F-01~F-06)
- 일정 여유 시 포함: 접수 마감 알림, AI 소요 시간 추정, 시험 회차 추천, 학기 회고 (선택 F-07~F-10)
- 제외: 네이티브 앱, 학교 포털·LMS 연동, 다른 사용자와 계획 공유, 결제

### 1.2 용어 정의

| 용어 | 정의 |
|---|---|
| 계획 | 사용자가 등록하는 수업·활동·프로젝트 한 건. 시작·종료 주차와 주당 소요 시간을 가짐 |
| 주차 | 사용자가 입력한 학기 시작일(1주차 월요일)부터 7일 단위로 센 번호. 1~16주차 |
| 가용 시간 | 사용자가 한 주에 학업·활동에 쓸 수 있다고 입력한 시간 (1~168시간) |
| 주차별 부담 | 해당 주에 걸친 모든 계획과 자격증 준비 시간의 합 |
| 부담률 | 주차별 부담 ÷ 가용 시간 |
| 준비 기간 | 자격증 시험일 직전 N주. 이 기간 동안 주당 학습 시간이 부담에 더해짐 |
| 사전 검토 | 새 계획을 저장하기 전에, 추가했을 때의 예보를 기존 예보와 겹쳐 보여주는 기능 |
| 맑음·흐림·폭풍 | 부담률 단계(여유·주의·과부하)를 사용자에게 보여주는 날씨 표현 |

### 1.3 요구사항 표기

- 기능 요구사항 ID는 제안서의 F-01~F-10을 그대로 쓰고, 세부 항목은 FR-01-1처럼 붙입니다.
- 비기능 요구사항은 NFR-분류-번호로 표기합니다.
- 우선순위는 필수(10/18까지 완료)와 선택(10/18 이후 착수) 두 단계입니다.

## 2. 시스템 개요

학기예보는 대학생이 학기 계획을 입력하면 주차별 소요 시간을 합산해 과부하 주차를 미리 보여주는 반응형 웹 서비스입니다. 핵심 가치는 일정을 "추가하기 전에" 감당 가능 여부를 판단하게 돕는 것입니다.

### 2.1 사용자 유형

| 사용자 | 설명 | 주요 사용 기능 |
|---|---|---|
| 비회원 | 로그인 전 방문자 | 로그인 (🔄 Google만) |
| 회원 | 수업 외 활동·자격증을 병행하는 대학교 2~4학년 | 계획 등록, 자격증 선택, 부담 예보, 사전 검토 |
| 운영자(팀) | 자격증 일정 데이터를 관리하는 팀원 | Supabase 대시보드에서 certificates 테이블 직접 입력·수정 |

별도의 관리자 화면은 만들지 않습니다. 운영자 작업은 Supabase 대시보드와 SQL 시드 파일로 처리합니다.

### 2.2 운영 환경

- 클라이언트: PC·모바일 브라우저 (최신 Chrome, Safari, Edge, Samsung Internet)
- 프론트엔드: React 19 + Vite + TypeScript, Tailwind CSS v4 + shadcn/ui, TanStack Query, React Hook Form + Zod, Recharts
- 백엔드: Supabase (Auth, PostgreSQL, Edge Functions, Storage)
- 배포: Vercel (GitHub main 브랜치 자동 배포), 패키지 관리 pnpm

### 2.3 제약 조건

- 개발 기간은 2026-10-13 ~ 2026-10-20 (8일), 팀원 4명입니다.
- Supabase·Vercel 무료 플랜 범위 안에서 운영합니다. Supabase 무료 프로젝트는 장기간 미사용 시 일시정지될 수 있습니다.
- 자격증 일정은 자동 수집하지 않고 팀이 시행 기관 공고를 보고 직접 입력합니다.
- 학기는 16주를 기본으로 가정합니다.

## 4. 부담 산출 규칙

모든 화면은 하나의 산출 모듈(`src/features/forecast/calc.ts`)이 낸 값만 사용합니다. 예보 그래프, 사전 검토, 회차 추천이 서로 다른 숫자를 보여주는 일을 막기 위해서입니다.

### 4.1 날짜를 주차로 바꾸기

학기 시작일 S는 1주차 월요일입니다. 날짜 d의 주차는 다음과 같으며, 1~16 밖이면 "학기 범위 밖"으로 처리합니다.

```
week(d) = floor((d − S) / 7) + 1
```

### 4.2 자격증 준비 기간

시험일이 속한 주차를 E, 준비 기간을 N주라 하면 준비 주차는 E−N+1부터 E까지(시험 주 포함 N주)입니다. 이 중 1~16주차에 걸친 주에만 주당 학습 시간을 더합니다.

### 4.3 주차별 부담과 부담률

i주차 부담은 그 주에 걸친 계획의 주당 시간에 시험 가중치를 곱해 더하고, 준비 중인 자격증의 주당 학습 시간을 더한 값입니다.

```
W_i = Σ_{p : s_p ≤ i ≤ e_p} h_p · m_{p,i}  +  Σ_{c : i ∈ prep(c)} s_c
r_i = W_i / A
```

- h_p: 계획 p의 주당 시간, s_p·e_p: 시작·종료 주차
- m_{p,i}: 계획 p가 수업이고 i가 중간 또는 기말고사 주차이면 1.5, 아니면 1
- s_c: 자격증 c의 주당 학습 시간
- A: 사용자 가용 시간

### 4.4 단계 판정

| 단계 | 부담률 | 표시 | 색 |
|---|---|---|---|
| 맑음 (여유) | 0.8 미만 | 맑음 | 녹색 |
| 흐림 (주의) | 0.8 이상 1.0 이하 | 흐림 | 주황 |
| 폭풍 (과부하) | 1.0 초과 | 폭풍 | 적색 |

판정은 반올림 전 값으로 하고, 화면에는 시간을 소수점 첫째 자리까지 표시합니다.

> 구현: 코드의 단계 이름은 `clear`(맑음) / `cloudy`(흐림) / `storm`(폭풍) 입니다.

### 4.5 검증 예시

제안서 시나리오(3학년, 가용 시간 주 50시간)의 8주차를 계산하면 폭풍이 나와야 합니다. 이 값을 산출 모듈 단위 테스트의 기준값으로 씁니다.

| 항목 | 계산 | 시간 |
|---|---|---|
| 3학점 수업 5과목 (보통) | 6 × 5 × 1.5 (중간고사) | 45 |
| 학회 활동 (보통) | 4 × 1 | 4 |
| 정보처리기사 준비 | 8 | 8 |
| 합계 W₈ | | 57 |
| 부담률 r₈ | 57 ÷ 50 | 1.14 → 폭풍 |
